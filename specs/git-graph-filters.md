# Git 图谱独立入口与单行筛选

## 产品规则

1. Git 工具浮层增加独立「Git 图谱」行，位于分支行之后。移除分支菜单中的图谱项，保留创建、切换分支。图谱仍使用现有弹窗，不新增 Side Pane 或页面。
2. `WorkspaceGitToolsEntry` 独立持有图谱打开意图，弹窗挂在 `PopoverContent` 外。点击图谱行先关闭 Git 浮层再打开图谱；不使用超时等浮层卸载。关闭图谱后焦点回标题栏 Git 图标。切工作区/服务 scope 时关闭旧图谱。
3. 有效 Git 仓库即保留标题栏 Git 工具入口，包括干净仓库、无上游和 detached HEAD。非仓库、Git 不可用及既有 Office 模式隐藏规则不变。徽标仍只显示实际文件/远程提交计数，干净 detached HEAD 无徽标。
4. 筛选栏始终一行：`文本或哈希 [.*] [Aa]`、`分支`、`用户`、`日期`。**不提供重置按钮，也不提供日期起止输入**。窄屏仅筛选栏内部横向滚动，不换行、不撑宽整个页面；文本与两个开关保持同组。
5. 文本或哈希匹配提交说明（标题和正文）或完整哈希；短哈希可以按子串匹配。默认字面匹配且忽略大小写；`.*` 开启 JavaScript 正则，`Aa` 开启区分大小写。两开关位于文本框右侧，提供选中态、`aria-pressed` 和中英 tooltip。正则固定 Unicode flags（区分大小写 `u`，忽略大小写 `iu`），无 `g`/`y`，每个字段分别匹配，不拼接不同字段产生跨字段命中。
6. 分支默认全部，可选择本地或已存在的远程跟踪分支，筛选该完整 ref 可达历史，而非仅检查 tip decoration。仅查询，不 checkout、不自动 fetch。分支名中的 `/` 不作为远程身份依据。
7. 用户指 Git 提交作者，候选为历史中的姓名/邮箱组合，默认全部；按所选身份精确匹配，不使用应用账号或当前 Git 配置替代。作者显示与筛选使用同一原始 `%an/%ae` 口径，不混入 `.mailmap` 规范化身份。
8. 日期下拉为 `全部时间`、`过去 24 小时`、`过去 7 天`、`过去 30 天`。与图谱当前 `authoredAtMs` 一致，筛作者时间，不使用 Git committer time 的 `--since/--until` 替代。范围是应用条件时刻向前的滚动时长 `[fromMs, toMs)`；同次分页固定边界，刷新或重新应用条件重新取当前时间。不因遇到较旧时间戳提前结束非单调历史扫描。
9. 分支、作者、日期与文本条件取 AND；文本与哈希命中取 OR。清空文本/下拉选择全部分别取消对应条件。文本连续输入可短暂合并查询，Enter 立即应用；下拉与开关改变后应用。合并仅用于输入请求频率，不掩盖事件同步。
10. 加载、错误、无匹配时筛选栏仍可操作。无效正则明确报错，不降级字面查询或空结果。零匹配与仓库没有提交使用不同提示；首页请求失败不显示“仓库没有提交”的成功空态。候选刷新后原先选中的分支/作者不再存在时保留原值标签，不展示“全部”却继续旧筛选；用户仍可选择全部取消。
11. 条件变化从第一页重新查询，复位选中/展开详情与滚动；旧查询或旧加载更多响应不能覆盖新条件。关闭图谱、切 scope 或服务实例变化后旧响应失效。分页响应必须先在唯一查询 owner 同步推进提交列表及游标，再释放正在加载的 admission；不能等 React commit 才推进游标，否则紧邻滚动事件会重复读取同一页。

## 查询契约与所有者

- `useGitGraphQuery` 是图谱本地条件、结果、加载状态、选中项和分页的唯一 owner；筛选栏受控，不写全局设置/会话状态。
- `IGitService.getCommitGraph` 是唯一历史查询路径。扩展可选 `filters` 与 `cursor`，保留旧 `workspacePath/maxCount/skip` 调用兼容。
- 新只读 `getCommitGraphFilterOptions` 提供完整分支 ref 和历史作者候选，候选来自同一用户可见历史，不能从首批 50 条结果推导。
- 服务入口运行时校验请求；命令使用 argv 数组，无 shell。拒绝 NUL、非法 ref/日期/游标和未知模式。分支只接纳现有 `refs/heads/**` 或 `refs/remotes/**` 并解析为 commit OID。
- 查询整个 repo 的用户可见历史：HEAD、本地分支、标签、远程跟踪分支；不使用 `--all`，不纳入内部 `refs/zcode/checkpoints`。空 HEAD 不应掩盖其他有效分支。
- **先匹配后分页**：按有界批读取历史，直到取得本页及下一条匹配项或真正扫描完。稀疏匹配和第二页以后的历史仍可搜索。不能扫描一批后把无命中误报 `hasMore=false`。
- 新分页游标固定起始 root OIDs、查询指纹、原始扫描位置及目标 scope，下一页按相同历史遍历序续读；不使用 `lastHash^` 丢弃并行分支。游标受完整性、作用域与资源上界校验，旧端无 cursor 仍按原 skip 兼容读取。
- 正则在可终止 worker 执行，表达式最多 512 字符，每批匹配预算 250ms，查询总预算 15s。历史每批 200 条，单次查询累计输出最多 32MiB、遍历位置最多 250,000 条、最多 256 个 root / 4096 个可见 ref；游标有效期 30 分钟。到预算或输出截断时明确失败，不阻塞 Host、不伪造完整结果。不增加生产日志中的正文、搜索文本或邮箱。
- 对外提交仍携带真实直接 parents；过滤后缺失的父节点只表示分页或隐藏边界，不把间接祖先伪装成直接边。布局引擎不在本次重写。
- 日期边界在 UI 应用时冻结并通过 filters 传递；游标绑定该边界，不在 Host 根据两端不同的时钟重新解释预设。

```text
标题栏 Git 图标 → shell Git 浮层
  → 独立图谱行 → 关闭浮层 → WorkspaceGitToolsEntry.graphOpen
                                → GitGraphDialog
单行筛选草稿 → useGitGraphQuery（应用时固定日期边界/请求代次）
  → 当前工作区 IGitService → GitCliRepo 有界历史扫描 → matcher worker
                                ├─ 精确分支/作者/作者日期 AND 文本或哈希 OR
                                └─ root 快照 + 查询指纹 + 扫描位置 → 下一页游标
  → 对应代次 commits/hasMore/cursor → 现有 GitGraphPane
关闭 / scope 切换 / 再应用 → 旧代次与旧分页响应丢弃
```

UI 隔离使用 `workspaceIdentity?.trim() || workspacePath`，并保持实际服务实例与远程 attachment 路由；Git cwd 使用 `workspacePath`。Desktop 本地、远程和手机复用已解析的目标 Git 服务，不按同路径回落本地。服务 RPC 不经过 Agent 会话协议，本次不修改 `zcode-protocol/index.ts`。

## 验收与正式验证

- 独立入口唯一、分支菜单仍可创建分支、收起 Git 浮层不卸载图谱、关闭焦点回图标；干净 detached HEAD 入口可达。
- 单行四组筛选无重置/日期输入；中英浅深色、桌面和 320/390px Web，栏内可横滚且页面无溢出。
- 字面元字符、正则、大小写、完整正文与短哈希 OR；分支/用户/日期组合 AND、四种时间预设及精确边界。
- 有效远程 ref、本地斜杠分支、同名不同邮箱、作者/提交者日期不同、非单调时间、隐藏 checkpoint refs。
- 超过首批 50 条才命中、稀疏匹配分页、翻页期间 ref 更新不重复、条件变化/关闭/scope 切换旧响应丢弃。
- 非法正则与耗时正则、错误/异 scope cursor、无效 ref、空仓库、Git 超时/输出截断，不降级或静默返回空结果。
- 补正式 services/UI 测试纳入根 typecheck 与 `pnpm test:desktop-regressions --suite git`。实际执行 `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`、改动文件格式检查。
- 浏览器使用本地虚构服务或系统临时仓库，不访问生产账号，不运行无关 About 原生测试；临时目录 finally 清理。
