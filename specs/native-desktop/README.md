# ZCode 原生桌面版：双轨产品与迁移规格

## 状态与范围

- 决策日期：2026-11-27。
- 用户已同意准备独立原生重构版；原版继续保留，不能修改 `main` 来迁就原生版。
- 技术方向：MyGo 的 Go 原生 UI，禁止用 WebView 承载工作台或以 Web 前端冒充原生版。
- 当前阶段：分支、工作目录、规格、完整重构任务书和验收准备。没有原生可执行程序，没有已完成的功能迁移，也没有已验证的性能收益。
- 执行入口：[完整重构任务书](reconstruction-tasks.md)，包含 50 项任务的范围、依赖、状态所有者、实现细节和验收条件；所有产品实现仍为未开始。
- 对齐基线：ZCode 4.1.3，提交 `f78689fd243dc02be37e38d6b34afa2137bdb4ac`。后续以实际检出的源码继续校验，不把这个提交视为永久冻结的协议。

## 工作与发布隔离

| 事项           | 原版                                | 原生版                                         |
| -------------- | ----------------------------------- | ---------------------------------------------- |
| 当前分支       | `main`                              | `native/mygo`                                  |
| 当前本地目录   | `F:/Han/demo/test01/ZCode-classic`  | `F:/Han/demo/test01/ZCode`                     |
| 产品路线       | 现有 Electron、React、Host 与 Agent | 计划 MyGo 原生工作台，分阶段适配 Host 与 Agent |
| 本轮允许的变更 | 无                                  | 本规格和 `apps/zcode-native/README.md`         |
| 发布状态       | 保持既有发行流程                    | 尚无发行流程或安装包                           |

两个目录是同一仓库的 Git worktree，不是复制粘贴的独立仓库。它们共享对象与分支引用，但有独立工作树和索引；一个目录的修改不会自动出现在另一个目录。未来的操作必须先核对分支和 cwd，不能从原目录启动脚本写入原生版，或反过来。

规则：

1. 按用户 2026-11-27 的切换要求，当前项目目录检出 `native/mygo`；`main` 在独立 `ZCode-classic` worktree 保留，分支引用和基线提交不变。不重写标签，不合并、提交或推送。
2. 现有 `packages/desktop`、`packages/ui`、CLI、协议、版本号、根工具链、根脚本与发行配置在准备阶段保持不变。
3. 原生应用的预留位置为 `apps/zcode-native/`，目前只放入口说明；后续 Go 模块、测试和资源必须在规格明确并通过架构门禁后添加。
4. 双版本不是原应用内的模式开关；不新增全局设置来切换框架，不把原生 UI 注入原版启动路径。
5. 原生版未来需要独立的应用身份、安装目录、更新通道、协议注册和测试数据根。具体值尚未写入配置；不得覆盖原版安装或向原版更新通道发布。
6. 默认隔离实验数据和凭据；兼容阶段也不能让两套进程直接并发写原版生产数据库。历史导入、共享历史与并发使用的策略要另立规格，不自动迁移或删除用户数据。
7. 接收主线更新时在原生分支中审阅和验证；不能自动把原生实现合回 `main`。

## 产品规则

### 必须保持

- 沿用当前设计体系的布局、密度、主题、字体语义和国际化，不改成框架默认外观。阅读基线为 [DESIGN.md](../../DESIGN.md)；插件商店术语以 [CONTEXT.md](../../CONTEXT.md) 为准。
- 相同用户动作应得到相同业务结果，包括输入、引用、发送、排队、停止、审批、计划、子代理、工作流、终端、分屏与恢复。
- 不能用新增专用输入框、额外发送入口、模式选择器或删除快捷键降低迁移难度。
- 原生版本的交互通过 [交互对等清单](interaction-parity.md) 验收；框架示例或一个计数器不能代表 ZCode 交互通过。
- 原生化与运行时优化是两项不同工作。兼容阶段允许保留独立 Node 侧车，必须明确进程与成本，不能因此声称已去除所有 JavaScript 运行时。
- 降低内存不能靠停止仍在运行的任务、减少约定并行度、丢失历史、去掉恢复保障或忽略隐藏终端来实现。

### 禁止默认降级的边界

当前内置浏览器直接依赖 Electron `<webview>`、页面 DOM 与 debugger/CDP。完全无浏览器引擎与任意网页的嵌入式交互不能同时满足。用户没有批准外置浏览器、截图流、删除该能力或改变元素选取方式。

PDF、DOCX、PPTX、Mermaid、公式和媒体预览也不能从 MyGo 基础组件推断为等价支持。任何替代引擎必须证明搜索、选择、复制、引用、导航、主题及权限语义；把内容转成图片不等于完整复刻。

这些项目记为产品与实现待决，不阻止准备规格，但在未明确并验证前，原生版不能标记为完整替代版。

## 状态所有者与事件顺序

目标边界如下，兼容阶段的具体进程适配需要在实现规格中确定：

```text
MyGo 原生工作台
  ├─ 唯一拥有：未提交草稿、焦点、布局、选区、局部展开状态
  └─ 只读投影：会话、队列、权限、任务与工作流状态
                    │ 用户动作形成有身份和幂等键的命令
                    ▼
原生传输 / 平台适配端口
  ├─ wire 校验、分片组装、ACK / 下行帧顺序、失效清理
  └─ 窗口、剪贴板、菜单、通知等原生能力
                    │
                    ▼
窗口级 Host 边界
  ├─ 本地 workspace 路由与进程生命周期
  ├─ 远端连接注册表、attachment、owner / lease
  └─ 本地 CLI 或远端已有 Host / runtime
                    │
                    ▼
CLI / Agent runtime
  ├─ CommandInbox 串行 admission、权限与 accepted queue
  ├─ 会话、任务、子代理、工作流及持久化的权威事实
  └─ 事件投影 / snapshot / delta
                    │
                    └─ 原生工作台只读投影，不再建立第二条业务写入路径
```

提交顺序必须保持：草稿校验 → 身份绑定 → 提交命令 → CLI admission / ACK → 权威事件与持久化 → UI 对账。ACK 之前到达的通知按既有订阅屏障排序，不能靠延时猜测正确次序。

- `workspaceIdentity?.trim() || workspacePath` 是身份 key；`workspacePath` 用于文件操作、cwd、Git 和展示。
- 远端链路贯穿 `workspaceIdentity` 与 `remoteSessionId`，不按路径代替身份，不在 Go 业务代码中手写另一套远端 identity 格式。
- 每个窗口的本地 workspace 共用窗口级 Host 边界；UI 和窗口调度层不拥有任务/session 业务状态。
- 手机 attachment 继续复用已有 Host/runtime，不为原生版或手机另起远程会话来绕过 owner/lease。
- `desktop-continuous` 与 `web-remote-replayable` 保持不同传输语义。纯原生桌面不是理由去改变手机恢复协议或删除 stale run 防护。
- 视图关闭、连接解除、运行时终止是不同动作；隐藏视图不能默认终止任务或 PTY。

## 协议与依赖规则

- 现有公开协议与服务接口是兼容来源：[V4 core](../../packages/shared/src/zcode-protocol-v4/core.ts)、[平台端口](../../packages/shared/src/platform.ts)、[现有 conversation transport](../../packages/ui/src/v4/transport.ts)。
- 基线 `V4_WIRE_PROTOCOL_VERSION` 为 3，不能把产品名“V4”当作 wire 版本 4；snapshot 的版本与物理 wire 版本分别处理。
- Go DTO、运行时校验和跨语言 fixture 必须源自同一合同。准备阶段不复制一套手写、宽松、无人维护的协议类型。
- 兼容适配需覆盖订阅、activate、命令 ACK、query 对账、分片、resync、取消和生命周期；只收发文本不算协议兼容。
- 复用 TypeScript services/CLI 时从公开入口和协议端口访问。原生 UI 不直接操作 Repo，不让业务 Service 依赖具体 Runtime。
- 新的 Go 层必须有平台适配和异步 IO 边界，不把网络、文件或模型调用放在 UI 线程。
- 实现阶段使用 architecture-governance，先检查既有边界并为 Go 模块明确纳管方式；现有 TypeScript 检查通过不能宣称新 Go 模块也已受控。

## 准备阶段验收

1. 原版 worktree `ZCode-classic` 检出 `main`，HEAD 与准备前一致，tracked/untracked 状态不出现本轮修改。
2. 当前项目目录 `ZCode` 检出 `native/mygo`，准备文件只出现在该目录。
3. 本规格明确两种产品、唯一状态所有者、协议边界、数据隔离和禁止默认降级项。
4. [交互清单](interaction-parity.md) 与 [性能基线](performance-baseline.md) 区分规划、源码证据、执行结果及缺口。
5. [原生版入口](../../apps/zcode-native/README.md) 记录实际环境、阶段清单和没有实现的事项；不提供不存在的 Go 启动、测试或构建脚本。
6. 实际执行 `pnpm typecheck` 和 `pnpm lint`，只在隔离 worktree 运行。依赖或构建限制、已有失败如实写入准备记录；不为把门禁变绿而修改原版代码。
7. 不升级全局 Go，不运行 `mygo init`、不启动 Electron/MyGo、不安装原生插件、不发布内容。本机 Go 1.26.4 与 MyGo v0.10.0 的 Go 1.27.3 要求不匹配，作为后续工具链前置条件。
8. 不遗留诊断脚本、截图、日志、临时配置或构建产物。独立安装的开发依赖属于后续复用环境，不复制原目录构建物冒充新基线。

## 迁移阶段与放行条件

本轮文档准备已完成，产品实现仍未开始。后续阶段按 [重构任务书](reconstruction-tasks.md) 统一编号：

- **P0，资格与合同（ND00–ND06，未开始）**：基线账本、框架与内容引擎资格、独立工具链、设计/服务/协议、双版本数据隔离。先解决浏览器与复杂预览的保真阻断。
- **P1，原生宿主、工作台与聊天（ND07–ND20，未开始）**：先打通真实 session 的创建、发送、排队、审批、停止和重连，再完成工作台、输入/引用、历史、分享、侧聊与状态。
- **P2，专业内容与工作流（ND21–ND30，未开始）**：文件、Git、终端、全部格式预览、浏览器、编排/动态工作流及详情/产物。
- **P3，设置、自动化与辅助面（ND31–ND43，未开始）**：17 个可见设置分区、引导/账户、自动化与闲时、Bots、导入、反馈及辅助视图。
- **P4，全面恢复和优化（ND44–ND48，未开始）**：远端/手机、scheduler/崩溃恢复、正式原生验证及同场景内存/延迟优化。
- **P5，双版本发行（ND49，未开始）**：全部功能账本放行、独立安装/更新通道、数据兼容和回滚；不得替换原版发行。

阶段名称是集成交付边界，不是已执行任务或耗时承诺。高风险内容资格和验证贯穿全过程，不能拖到最后才发现缺失。每项实现都先补相应 spec 和测试，再写代码。
