# Git 工具与提交弹窗刷新一致性

## 背景

2026-11-23：Git 工具浮层仍显示旧的 `+1 -1`，提交弹窗重新读取后已经显示 5 个文件、`+131 -14`。当前代码存在两条已确认的刷新缺口：文件监听采用 60 秒尾沿防抖，连续文件事件会不断延后刷新；提交弹窗直接读取服务并只更新自己的文件快照，外层 `useGitRepository` 没有收到该结果。

本次修复刷新传播与调度，不改变提交范围、部分暂存、Git 仓库作用域或协议语义。

## 产品规则

1. **唯一 Git 基线所有者**：当前工作区的 `useGitRepository` 接受 Git 刷新请求、执行既有 `IGitService.refresh`、按请求顺序发布完整 `GitRefreshResult`。标题栏徽标、Git 工具浮层、Git 面板和提交弹窗的基线均从该刷新能力获得；不建立第二个仓库事实缓存或服务端广播状态。
2. **主动打开立即读取**：打开 Git 工具浮层或提交弹窗时请求工作区所有者刷新，不等待文件监听防抖。关闭浮层/弹窗不额外读取 Git。
3. **同一结果同步**：提交弹窗加载所消费的 `summary`、`stagedChanges`、`unstagedChanges` 与发布给外层的基线来自同一次刷新结果。不能先独立查询弹窗，再触发第二次外层查询并视为原子同步；不能把弹窗勾选后的合计直接写进外层统计。
4. **自动刷新有界**：单次或短批文件事件以 350ms 静默窗口合并；连续文件事件最多等待 2000ms 即触发一次刷新。该最大等待时间从本批首次事件计算，后续事件不能重置。调度只合并通知，不用延时掩盖跨视图同步。
5. **限制重复 I/O**：同一工作区刷新串行执行；并发刷新意图合并，刷新期间的后续变更最多保留一个待执行请求。请求合并保留 `includeIdentity` / `includeBranchComparison` 的扩展需求。主动查询不会被静默丢弃；操作后的刷新不能复用操作之前的过期结果。
6. **生命周期与陈旧结果**：工作区切换、远端连接/服务切换和卸载后，旧请求不再发布结果。未完成的弹窗加载在关闭或切换工作区后不能重新填入文件、打开弹窗或清空新弹窗的草稿。最新有效请求才能更新事实；失败沿用现有错误展示与日志，不把旧事实伪装为新结果。
7. **保留局部选择态**：提交弹窗的排除集合、折叠集合、提交消息与机器消息的选择快照仍由现有组件持有；打开/切换分支时重置选择，普通外层刷新不重置弹窗草稿。
8. **相同基线不代表相同统计范围**：外层统计全部 staged + unstaged；提交弹窗按当前勾选和部分暂存归属计算。取消勾选、会话过滤或已暂存文件另有工作区余量时，内外合计可以合理不同；不得为了数字一致而改变实际提交范围。
9. **平台与身份边界**：身份使用 `workspaceIdentity?.trim() || workspacePath`；文件执行仍使用 `workspacePath`。复用当前工作区依赖注入的 Git/文件监听服务，不以路径相同合并不同远端身份。Linux 的 metadata-only 监听边界保持不变，主动刷新在所有平台可用。
10. **无远端业务协议改动**：Desktop 的连续会话链路和手机 Web 的可恢复链路均通过同一个工作区刷新所有者读 Git；本修复不修改 Agent stream/snapshot/queue、不新增 Host/Main 状态或 RPC。

## 所有者与接口

- `useGitRepository`：工作区 Git 基线、请求序列、刷新生命周期与旧结果隔离。
- 工作区级 React Context：仅传递可 await 的刷新能力，不保存结果或业务事实；由 `App` 将现有所有者注入工作区子树。
- `useGitAutoRefresh`：监听注册与有界通知调度，不保存 Git 快照；清理时取消静默和最大等待定时器。
- `GitActionMenu`：提交草稿及由本次刷新基线派生的提交预览；加载完成前检查当前弹窗/工作区请求代。
- 保留旧 `onRefreshGit(): void` 动作接口，内部交给同一刷新所有者；避免向分支、拉取和侧栏接口传播第二种事实写入路径。

```text
文件监听事件 → 350ms 静默 / 2000ms 最大等待调度 ─┐
打开 Git 浮层 / 提交弹窗（不经防抖）────────────┤
Git 操作完成 / 手动刷新 ──────────────────────┤
                                              ↓
                        useGitRepository（按工作区身份绑定的唯一所有者）
                          → 串行 / 合并刷新意图
                          → IGitService.refresh（既有工作区服务）
                          → 有效请求发布同一份 GitRefreshResult
                            ├─ App → Git 工具模型 / 徽标 / Git 面板
                            └─ 本次提交弹窗 → 文件预览 → 勾选/提交草稿

工作区 / 服务切换或卸载 → 旧请求失效，不发布结果
弹窗关闭 / 重新加载     → 旧加载代失效，不写回草稿
```

## 验收场景

1. 外层已有旧值 `+1 -1`，新基线含 5 个未暂存文件、合计 `+131 -14`；打开提交弹窗后，两处显示同一次读取的新统计，不等待 60 秒，不额外查询第二次来同步外层。
2. 只打开 Git 工具浮层，立即请求刷新；关闭不刷新，纯重渲不重复请求。
3. 1 次文件通知在 350ms 静默后刷新；连续事件每 100ms 到达，仍在首次事件后 2000ms 内发出刷新。
4. 同一批连续通知不创建每事件一次的 Git 请求；请求未完成时再次收到多个通知，只排一个后续请求，且操作后请求读取新状态。
5. 并发基础/identity/branch comparison 请求保留扩展需求；任何一个 await 的调用方都不能拿到不满足需求的结果。
6. 请求失败后能再次刷新；失败结果不污染当前工作区的成功快照。
7. 相同 `workspacePath`、不同 `workspaceIdentity` 的请求互不覆盖；切换工作区/远端连接后返回的旧结果不能影响新工作区。
8. 弹窗加载中关闭再打开，旧请求后返回不覆盖新预览、草稿或 loading 状态。
9. 全选 5 个文件时显示 `+131 -14`；取消勾选只改变弹窗合计，外层仍显示全部改动。部分暂存文件的余量不被错误加入提交。
10. Desktop 宽屏和手机 Web 窄屏运行真实 Git 工具/提交弹窗组件，验证主动打开、内外同步、选择态以及无横向溢出；不操作真实用户仓库提交。
