# 内置子智能体跨视图颜色一致性

## 背景

2026-11-23：会话中的 `reviewer` 使用亮红色，而设置列表的颜色点呈玫瑰色；用户报告其他内置编排角色也常被显示成同一红色。当前源码确认：聊天组件仅查询已加载配置，随后优先采用工具输入/旧元数据颜色、最后按原始名称 hash；它没有使用内置角色目录兜底。设置颜色点和会话身份文本还分别使用不同亮度/透明度的色板。

本次修复所有内置角色的身份色来源及跨视图表现，不改角色权限、工具范围、模型选择或任务运行状态。截图所用构建和现场事件尚未复现，不将某一种输入推断成唯一原因。

## 产品规则

1. **内置配色唯一来源**：复用公开 `@zcode/shared` 的 `BUILT_IN_SUBAGENT_DEFINITIONS`，不在 UI 或 CLI 再维护第二份角色配色表，不把 reviewer 改成另一种角色颜色。

   | 内置名称        | 定义颜色                            |
   | --------------- | ----------------------------------- |
   | general-purpose | blue                                |
   | Explore         | cyan                                |
   | architect       | purple                              |
   | frontend        | teal                                |
   | backend         | green                               |
   | ui-designer     | pink                                |
   | tester          | orange                              |
   | reviewer        | red（既有 UI 色板的 rose 色相）     |
   | bug-fixer       | yellow（既有 UI 色板的 amber 色相） |

2. **统一身份色解析**：设置列表、会话 Agent 工具行、运行中智能体身份和编排步骤角色使用同一 UI 纯函数取色。已匹配当前工作区配置的角色优先使用其声明颜色；内置角色即使配置未加载或缺旧字段，也按内置定义取色。只有未匹配配置且不是内置的角色，才采用合法工具颜色或稳定的名称兜底色。
3. **内置目录优先于旧通用元数据**：明确为内置的 `frontend`、`architect` 等不能被工具数据中的统一 `red` 覆盖。运行时已归一化的权威子智能体类型优先识别；不根据任务描述、状态或是否执行失败选择身份色。
4. **名字归一化仅用于匹配**：兼容运行时已有的 trim、NFKC、小写与空白/连字符/下划线归一化，支持 `ui_designer` / `UI-DESIGNER` / `ui designer` 等；显示名保持既有原文，不做本地化或改写。配置匹配先精确，再唯一归一化匹配；多义结果不猜测某一个自定义角色。
5. **命名空间与自定义角色隔离**：不截掉 `plugin:reviewer` 等完整名称的命名空间来套内置颜色。自定义/插件已匹配定义的声明颜色优先，缺颜色时按该定义名称稳定兜底。只识别实际内置名及既有 built-in 稳定 ID，不把任意 ID 的末段当内置。
6. **跨位置使用同一身份色**：同一主题下，设置列表颜色点和会话/面板身份文字使用同一身份色映射，不分别使用半透明点色和高饱和文字色。颜色选择器可保留既有色板表面布局，但身份展示点不能另选一套颜色。
7. **状态色独立**：运行中/等待/阻塞、编排成功/失败、错误文本、停止按钮等仍用现有状态语义色。身份为 reviewer 不代表失败；运行失败也不能把所有角色名染红。动态 workflow 图里的实例头像色板用于区分实例，属于不同语义，本次不改。
8. **工作区隔离**：配置读取以 `workspaceIdentity?.trim() || workspacePath` 及既有 provider key 为准。同路径的不同远端工作区不得互相使用颜色；旧单例配置只有在其 loaded identity/path/provider 与当前工作区一致时可复用。没有可匹配配置时内置配色仍稳定，不发起新的网络读取或维护第二份颜色 store。
9. **加载前后稳定**：所有内置角色的无配置首帧、配置加载后和历史/恢复视图保持相同身份色；只在对应自定义定义的显式颜色确实改变时更新。配置读取不新增 RPC、不修改 Agent 协议或持久化 schema。
10. **平台与主题**：Desktop 与手机 Web 复用同一组件/解析器；明暗主题中的文字均保持可读。角色名、截断、点击子会话、Stop 与编排状态顺序保持不变。

## 状态所有者与接口

- 内置角色元数据：`packages/shared/src/builtin-subagents.ts`，纯目录，已有 services / CLI 的共同输入。
- 已加载运行时定义：既有 `subagentsContextStore`，按身份 + provider 分桶；必要时读取已匹配的旧 `subagentsStore` 快照，不复制到新 store。
- 身份匹配、兜底及颜色映射：`packages/ui/src/lib/subagentColors.ts` 与既有 `subagentColorUsage.ts` 的统一纯函数；组件只消费结果。
- UI hook：订阅当前工作区的现有配置，提供统一解析能力，不主动拉取、不保存颜色事实。
- 名字事实和状态事实：继续由现有会话投影/工具显示字段拥有；颜色只是这些事实的派生展示。

```text
shared 内置定义 ──────────────────┐
当前工作区已加载 AgentSummary ───┼─ 统一身份匹配/颜色解析（纯函数）
非内置的合法旧工具颜色 ──────────┘      ├─ 设置列表身份点
                                       ├─ 会话 Agent 名称
                                       ├─ 状态面板智能体名称
                                       └─ 编排步骤角色

snapshot status → 既有状态词/图标语义色（独立，不参与身份取色）
workspaceIdentity / provider → 既有配置桶（不跨远端身份复用）
```

## 验收场景

1. 无任何已加载配置时，逐一显示全部内置角色，颜色与目录逐项一致，不能统一红色。
2. 为所有内置工具行传入旧 `color: red`，仍分别显示各自目录色（blue/cyan/purple/teal/green/pink/orange/red/yellow）；reviewer 保留 rose 色相，bug-fixer 使用 amber 色相。
3. 为全部内置角色加载当前工作区目录，加载前后取色一致；同名工具摘要、状态面板角色与设置颜色点使用相同身份色。
4. `ui-designer` / `ui_designer` / `UI-DESIGNER` / `ui designer` 与其既有 built-in ID 取相同颜色，显示名原文不变；Explore 的大小写也不导致颜色变化。
5. `plugin:reviewer`、带声明颜色的同名自定义定义和不同稳定 ID 不被误认成内置；自定义声明颜色优先。
6. 两个归一化后相同的自定义定义发生歧义时，不随机选其中一个；精确名称/ID仍可唯一匹配。
7. 同路径两个不同 `workspaceIdentity` 的配置色不同，聊天及状态面板分别读取自己的颜色，不能回退到另一个工作区的旧单例。
8. running/waiting/blocked 的同一角色身份色不变，状态词仍按现有 warning/neutral/destructive 展示；编排失败不染红其他角色名。
9. 浏览器运行真实设置/工具行/状态面板组件，在明暗主题及 390px 手机宽度断言全部内置角色身份颜色、取色一致、长名不溢出和既有交互可用。

## 验证入口

- 新增正式纯函数回归测试覆盖全部内置角色、优先级、归一化、命名空间、工作区隔离和所有颜色映射；纳入根 `pnpm typecheck` 的 UI 测试入口。
- 复用现有子智能体颜色占用/Agent 工具显示/状态身份测试，检查展示与实现相符。
- 交互回归脚本与截图仅存系统临时目录，验证后清理；不写入真实用户配置或会话。
- 执行 `pnpm typecheck`、`pnpm lint` 和 `pnpm architecture:check --changed`，如实报告结果。
