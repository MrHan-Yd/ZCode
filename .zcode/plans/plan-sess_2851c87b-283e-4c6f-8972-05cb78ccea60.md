## 问题定位（`@` 引用文件扫描）

`@` 搜索与 native 工具（bfs/ripgrep/ugrep，只服务 Agent 的 Bash）无关。真实链路是：
renderer `MentionPlugin` → `useFileMentionProvider` → RPC → Host `fileService.searchWorkspaceFiles` → 内存索引 + 模糊打分。

低性能设备上的四个热点，全部在源码注释里留有实测痕迹：

1. **没有防抖**：`MentionPlugin.tsx:152` 只有 `useDeferredValue`（延后渲染，不减少请求）。每次按键都发一次 RPC。
2. **不可取消**：`workspaceFileSearch.ts:25-41` 对全部候选（可达数十万）分批打分，无 token/abort；`fileMentionProvider.ts:88-90` 只丢弃过期响应，Host 仍把旧查询算完。快速输入时请求堆积、CPU 占满。
3. **未命中补扫会全仓重扫**：`fileMentionProvider.ts:73-78` 带 `refresh:true`，`fileService.ts:281-289` 让它绕过缓存与 in-flight 去重 → 连续不同的 miss query 触发多次重叠的 `readdir` 全仓扫描（注释记录 37 万文件即使并发化也要数秒）。
4. **打开面板做一次全量排序**：空 query 走 `shared/workspaceFileSearch.ts:229-236` 的 `sortDefaultWorkspaceFileSearchCandidates`，对全部候选 map+sort+map 三趟，只为取前 10 条。

## 变更

**1. renderer：真正防抖（新增 `packages/ui/src/hooks/useDebouncedValue.ts`，接入 `MentionPlugin.tsx`）**
- 对送入四个 mention provider 的 query 加 ~150ms 尾防抖；query 为空时立即生效，保证 `@` 一打开就出预览，不引入额外等待。
- 保留 `useDeferredValue`（渲染优先级），两者互补：防抖减请求数，deferred 保输入跟手。
- 快速输入从「每键一次 RPC + 全候选打分」变成「停顿后一次」。

**2. host：可取消（`fileService.ts` + `workspaceFileSearch.ts`）**
- `searchWorkspaceFiles` 按 workspaceKey 维护递增的查询 token；`searchHostFileCandidates` 新增可选 `shouldAbort`，每批（2048 条）检查一次，被更新查询取代就提前返回已得结果。
- 过期响应本来就会被 renderer 按 query 身份丢弃，所以提前返回部分结果语义安全；只有最新查询会完整计算。快速输入时 CPU 占用大幅下降。

**3. host：补扫节流 + 并入单飞（`fileService.ts`）**
- `refresh:true` 不再无条件绕过 in-flight 去重：同签名的在途扫描直接复用。
- 新增最小重扫间隔（`WORKSPACE_FILE_LIST_FORCE_REFRESH_MIN_GAP_MS`，约 5s）：缓存比间隔还新时，refresh 直接复用索引，不再全仓重扫。挡住「连续 miss → 连续全仓 readdir」。
- 保留 `refresh` 的原始目的：外部新建的文件仍能在下一轮补扫可见。

**4. host：空 query 快路径（`workspaceFileSearch.ts`）**
- packed 索引本身已按「目录优先 + 路径」排好序，空 query 现有语义是「文件优先、再目录，保持索引顺序」。用一次边界扫描取前 `limit` 条即可复现同一顺序，去掉对大仓库的三趟全量排序。
- 其余调用方（renderer worker 路径）不改，只改 Host 的 `searchHostFileCandidates`。

**5. 不做的事（明确取舍）**
- 不加新的设置开关：现有 `performanceMode` 是死开关，且这些优化是自适应的，不该让用户去调。
- 不降低 1000 条上限、不做「大仓库自动少返回」：`mentionSearch.ts:5-8` 的注释明确该上限是为了不出现「结果不全」，降级会改变产品行为。
- 不动 60s TTL 与缓存条数：每份索引持有已解码的候选数组，放大条数会成倍吃内存，反而伤害低配设备。
- 不引入文件 watcher / 索引持久化：属于结构性改造，风险高，留作后续。

**6. spec 与测试**
- 新增 `specs/mention-file-scan-performance.md`：记录防抖时长、token 取消语义、补扫间隔、空 query 顺序约定与验收场景。
- 新增 `packages/services/test/workspaceFileSearch.test.ts`：空 query 快路径顺序与旧实现一致、`shouldAbort` 提前返回、补扫间隔内的 refresh 复用索引、miss 不重复全扫。

## 预期效果

- 快速输入：请求数从「每键 1 次」降到「停顿后 1 次」；被取代的查询提前退出，不再把 Host CPU 占满。
- 未命中：不再触发连续全仓扫描。
- 打开 `@`：大仓库上省掉一次数十万条的全量排序与三趟对象分配。
