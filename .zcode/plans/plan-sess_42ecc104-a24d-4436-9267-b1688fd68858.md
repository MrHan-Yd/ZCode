## 关键设计决策

**用 Device Flow，不用回环端口。** GitHub OAuth App 不支持 PKCE，回环授权必须内嵌 client_secret（可被提取）；且 web/手机端拿不到 `zcode://` 深链，两端要各写一套。Device Flow 无需 secret，`platform.openExternal` 在 desktop 与 web 都已可用，两端共用一套代码。

**沿用仓库既有基建，不新造：**
- 设备码轮询照抄飞书应用注册的形态（`packages/services/src/bots/providers/feishuAppRegistration.ts` 的 `device_code` / `user_code` / `interval` / `expires_at` + `authorization_pending` / `slow_down` / `expired_token` 分支）；UI 轮询照抄 `packages/ui/src/BotsDialog.tsx:386-499` 的「等上一次返回再排下一次」写法，不堆叠 RPC。
- 凭据存储复用 `ICredentialService`（`packages/services/src/credential/credential.ts`，AES-256-GCM 落 `credentials.json`），key 用 `github:oauth:access_token`。

**状态所有者**：token 的唯一所有者是 host 侧 `GithubAuthService`（经 `ICredentialService` 持久化）；UI 只读状态、只发命令，不缓存 token 明文。设备码是**无状态**的——`beginDeviceAuth` 把 `deviceCode` 返给 UI，UI 每次 poll 带回来，host 不保存中间态（与飞书先例一致，避免多窗口/重连下的状态错位）。

**页面 id 不改**：导航项 id 仍是 `modelSmartConfig`，只换 `titleId` 与渲染组件。这样不动 `SettingsSectionId` 联合类型、`HIDDEN_SETTINGS_SECTIONS` 和「上次停留设置页」的持久化。

## 时序

```text
UI(未登录) ──点击「登录 GitHub」──► platform.openExternal(verification_uri)
   │                                        │ 用户在浏览器输 userCode 并授权
   └─ service.beginDeviceAuth() ──► POST github.com/login/device/code
        ◄── { deviceCode, userCode, verificationUri, interval, expiresAt }
   └─ 轮询 service.pollDeviceAuth({ deviceCode })  间隔 = interval（slow_down 则 +5s）
        └─ POST github.com/login/oauth/access_token
             ├ authorization_pending     → 继续轮询
             ├ slow_down                 → 间隔 +5s
             ├ device_flow_disabled      → 提示去 OAuth App 勾选 Enable Device Flow
             ├ access_denied / expired_token → 终止并提示
             └ access_token              → 写 ICredentialService → GET api.github.com/user
                                            ◄── { login, name, avatar_url } → UI 显示已登录
```
