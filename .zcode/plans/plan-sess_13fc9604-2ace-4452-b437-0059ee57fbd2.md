# 模型智能配置：本地数据源 + 远端同步

## 目标（与你的确认一致）
- 现有「智能配置自动填入」逻辑**不改**，只是把它的**数据源**变成可同步的：默认读本地文件，点按钮才从你的 gist 拉取覆盖本地。
- 设置页新增**独立一栏**展示这些参数 + 一个「从远端仓库同步」按钮。
- 同步地址固定为你的 gist（不可改）。

## 数据流
```
gist(raw JSON) ──[点击同步]──▶ ~/.zcode/v2/model-smart-config.json ──[每次 read 新鲜读取]──▶
   合并进内置模型规则层(排在 builtin 之后、personal 精确规则之前) ──▶ 现有 resolveModelConfig 自动填入
```
优先级：`builtin 规则 → 同步规则(覆盖 builtin) → 个人精确规则(最高)`，与现有解析顺序完全兼容。

## 我提议的「好添加」格式（`model-smart-config.json`）
扁平、贴近语义，新增模型只写你要覆盖的字段（缺省字段自动继承内置默认）：
```json
{
  "schemaVersion": 1,
  "revision": 1,
  "models": [
    { "modelMatch": "gpt-7.*", "contextWindow": 400000, "maxOutputTokens": 128000,
      "reasoningLevels": ["minimal","low","medium","high"], "supportsImage": true },
    { "providerId": "deepseek", "modelId": "deepseek-v5", "contextWindow": 256000 }
  ]
}
```
- `modelMatch`（正则，作用于任意 provider）或 `providerId`+`modelId`（精确），二选一。
- 参数：`contextWindow` / `maxOutputTokens` / `reasoningLevels` / `supportsImage|Video|Audio|Pdf|Text` / `supportsToolCall` / `supportsJsonSchemaOutput` / `supportsNativeWebSearch` / `supportsMidConversationSystem` / `enabled`。
- 解析时映射为现有精确/正则规则 + 稀疏 `ModelConfig`，走的是原有 `modelConfigDataSchema`，无需新的解析机制。

## 实现清单
1. **spec**：新增 `specs/model-smart-config-sync.md`（产品规则、状态所有者、接口、验收场景）。

2. **provider（纯逻辑，无 IO）** `packages/provider/src/config/model-smart-config.ts`
   - `modelSmartConfigFileSchema`（zod，扁平格式）+ `parseModelSmartConfigRules(input): ModelConfigRules`（映射为 `model`/`provider-model` 规则）。
   - `mergeModelConfigRules(a, b) = new ModelConfigRules([...a.rules(), ...b.rules()])`。

3. **provider-node（本地文件源）** `packages/provider-node/src/model-smart-config-source.ts`
   - `NodeModelSmartConfigRulesSource implements ProviderSource<ModelConfigRules>`：`read()` 每次读盘（缺失/损坏→空规则，不阻断启动），`onDidChange` 用 `fs.watch`+轮询兜底。
   - 路径常量 `MODEL_SMART_CONFIG_FILE_NAME = "model-smart-config.json"` + env `ZCODE_MODEL_SMART_CONFIG_FILE`（加进 `runtime-paths.ts`）。

4. **合并接入（唯一注入点）** `packages/provider/src/config-service.ts` + `packages/provider-node/src/provider-config-runtime.ts`
   - `ProviderConfigService` 增加**可选**依赖 `modelSmartRulesSource?`；`read()` 里 `zcodeBuiltinModelRules = merge(builtin, synced)`，并把 synced revision 计入 snapshot `revision`（否则 registry 会因 revision 未变而短路，同步不生效）。
   - 在 `provider-config-runtime.ts` 构造该源并注入；默认路径 `getAppConfigDir()/model-smart-config.json`。resolver/registry 不动。

5. **services（同步服务 + RPC）** `packages/services/src/model-provider/modelSmartConfig.ts` + `modelSmartConfigService.ts`
   - `IModelSmartConfigService { read(); syncFromRemote(); }` + descriptor，channel `ServiceChannels.ModelSmartConfig`。
   - `syncFromRemote`：用 host 的 `fetch`（`AbortSignal.timeout(20s)`、`credentials:"omit"`、体积上限、zod 校验）拉 gist raw URL，`atomicWriteText` 原子写本地，返回新视图。固定 URL 常量 = `https://gist.githubusercontent.com/MrHan-Yd/23347ceed833b414bd96e507facce432/raw`。
   - 注册进 `createLocalServices` 链、`IServiceAccessor`、`RemoteServiceAccess`；浏览器安全入口只导出描述符/类型。

6. **UI** `packages/ui/src/settings/ModelSmartConfigSection.tsx`
   - 默认读本地（`read()`）；展示本地文件路径、revision、规则列表（匹配模式 + 关键参数）；「从远端仓库同步」按钮 → `syncFromRemote()` → 成功后调 `providerSettingsService.refresh(...)` 使新规则生效 → 重新 `read()` 并 toast。
   - 注册设置分区：`settingsNavigation.ts` 的 `SettingsSectionId`+`isSettingsSectionId`、`settingsPageConfig.ts` 的 `BASE_SETTINGS_SECTIONS`（放在 `basics` 组、`modelProvider` 之后，图标 `SlidersHorizontal`）、`SettingsPage.tsx` 渲染分支（包一层 `<ServiceProvider services={localHostServices}>`）。

7. **i18n**：`settings.modelSmartConfig.*`（title/description/remoteUrl/sync/synced/syncFailed/localPath/empty 等）在 `zh-CN.ts` 与 `en-US.ts` 同步添加。

8. **测试**（`node:test`，`packages/services/test/` 惯例：`mkdtemp`+`setDataBaseDir`+`watch:false`）
   - 扁平格式→规则映射的单元测试；经 `createProviderConfigRuntime` 注入临时 smart-config 文件，断言 `resolveModelConfig` 能对新模型填入同步参数；同步服务的文件落盘/校验失败用例。

9. **gist 内容**：按上面格式生成起始内容（含示例条目）并写入 gist。
   - ⚠️ 环境里没有 `gh`，也没有 `GITHUB_TOKEN`/`GH_TOKEN`（只有 Git Credential Manager）。我会**先生成完整内容**，并尝试用 git 以你的凭据推送到该 gist；若推送需要交互凭据或失败，我会把最终内容和一条推送命令交给你，由你粘贴/执行，不会阻塞其它实现。
